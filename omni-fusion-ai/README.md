# OmniFusion Studio V7

A transparent multi-model AI development studio that uses one OpenRouter key to coordinate specialist models and produce real, downloadable project files.

## What changed in V7

V7 is not a model race and does not accept a written claim that a project was created. The workflow passes actual work and files through a visible sequence:

1. Product Lead creates the factual brief and acceptance criteria.
2. Content Strategist writes usable copy and information hierarchy.
3. UI/UX Designer defines the responsive interface and design system.
4. Frontend Architect creates the file and implementation plan.
5. Frontend Developer returns structured project files.
6. QA Reviewer inspects those actual files.
7. Fixer Developer returns corrected complete files.
8. Release Validator runs deterministic checks plus a model review.
9. Release Packager creates a real ZIP download.

Every later model receives the visible work from earlier teammates. The Team Room shows model IDs, handoffs, provider failures, file creation, repairs, and validation events.

## Studio features

- One OpenRouter server-side key
- Automatic selection of diverse usable models
- Optional manual model selection
- Actual project file explorer
- Editable code panel
- Working preview for static HTML projects
- File-change diff view
- Deterministic and AI validation report
- Downloadable ZIP generated by the backend
- Ask an individual teammate a follow-up
- Apply team notes back into the project files
- Strict or warning-only multi-model integrity setting
- Local project history
- Static multi-file, single HTML, Next.js, and automatic output modes
- Searchable AI integration compatibility library

## Update an existing GitHub/Vercel installation

1. Extract the V7 ZIP.
2. Open the existing `omni-fusion-ai` directory in the GitHub repository.
3. Upload everything inside the new `omni-fusion-ai` directory.
4. Replace matching files and commit to `main`.
5. Vercel should deploy the commit automatically.
6. Keep the existing Vercel Root Directory set to `omni-fusion-ai`.
7. Keep the existing environment variables.

## Required environment variables

```env
OPENROUTER_API_KEY=your_key
OPENROUTER_MODEL=openrouter/free
```

Optional:

```env
APP_NAME=OmniFusion AI
APP_PASSWORD=
PUBLIC_SITE_URL=https://your-project.vercel.app
OPENROUTER_ALLOW_PAID=false
```

When `OPENROUTER_ALLOW_PAID=false`, automatic selection prefers free models. Availability and capacity are controlled by OpenRouter and the underlying providers.

## Integrity behavior

The verified collaboration badge is based on model IDs returned by completed provider calls. It is not based on animation or the requested model name.

- **Warn and finish:** delivers files even when fewer unique models respond than requested.
- **Strict:** blocks ZIP release until the configured minimum number of unique model IDs has completed work.

## Real artifact contract

The Developer and Fixer must return a structured project object containing complete files. If a model returns only prose, V7 attempts to recover an HTML document; otherwise the step is marked incomplete instead of pretending files exist.

## API routes

- `GET /api/status` — provider and OpenRouter catalog status
- `POST /api/team-step` — short visible teammate handoffs
- `POST /api/project-step` — build, review, repair, apply, and validate actual project files
- `POST /api/package-project` — create the downloadable ZIP
- `POST /api/image` — optional image generation compatibility
- `POST /api/speech` — optional speech generation compatibility

## Testing

```bash
npm run check
npm test
```

The included tests cover provider routing, short-request collaboration, OpenRouter selection, structured project recovery, deterministic validation, ZIP creation, and a complete mocked build/review/repair/validate workflow.

## Security

API keys stay in Vercel environment variables and are not sent to the browser. Do not commit `.env` files or secrets to GitHub.
